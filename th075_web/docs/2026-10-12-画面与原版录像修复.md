# 画面与原版比赛录像修复（1.0.1）

本轮由用户提供的三张截图及 13 份原版比赛录像触发。此前组件测试和网页自录回放并未覆盖真实场景合成，不能据此认定没有画面问题。

## 已定位的根因

1. GraphicsDevice 初始化将 alpha 运算错误地设为只取纹理 alpha。原版 0x401540 明确设置 texture-stage ALPHAOP=MODULATE（4），乘上顶点透明度。遗漏导致 alpha=0 的未选角色、文字、过渡图层仍显示。已恢复乘法；继续采用共享 SDL3/WebGL2，未引入 D3D 运行时。
2. 应用场景绘制和战斗绘制漏掉原版 BeginTarget/BeginFrame 的颜色及深度清空。原版 0x402690 使用 clear flags=3、clear color & 0x0fffffff。已在两种实际绘制入口清空；转场捕获仍在切换前完成。仅修改 TH075 接入层，共享 Renderer.cpp 保持不变。
3. ReplayStreams 将辅助队列耗尽作为录像结束，但原版 0x4142d0 检查主输入队列。双人比赛辅助队列为空。已改为最后一个主输入被消费后立即置结束状态，辅助队列不改变结束标志；空输入录像同样处理。

## 回归方法

- scene-composition.test.mjs：真实 SDL3/WebGL2 GPU 检查零/半/满顶点 alpha；自然进入故事选人、切换角色、取消返回；从故事选人、设置、Music Room、战绩、录像、开场返回后整张 640×480 标题像素与干净标题完全相同。
- replay-eof.test.mjs：用原版二进制主循环和 C++ 场景执行同一份短输入样本。修复前原版 phase=6、C++ phase=0，修复后同帧结束且下一帧均返回录像菜单。
- recorded-match.mjs：实际原版主战斗循环与 C++ BattleScene 连续执行用户录像，逐帧比较位置/速度/动作、血量、灵力、符卡状态、输入历史相关状态、主输入/随机/辅助/事件游标、比赛阶段、倒计时及场景退出值。原版通过开发用 Unicorn 执行；图形、音频、磁盘边界不参与此比较。初始通用角色状态由 C++ 提供，原版派生构造器实际执行，独立构造/重置测试另存；此项不是原版图像或声音逐像素比对。
- original-replay.test.mjs：真实浏览器导入第一份比赛录像并完整播放 14,441 帧，状态与上述 C++ 场景一致，覆盖进入战斗、移动、出招和命中。
- full-flow.test.mjs 与 audio-browser.test.mjs：自录回放、故事七面和结局、续关、全角色装载、各模式及实际混音回归。自录样本最后一帧按独立原版 EOF 证据预期为 Exit，不再预期无限留在比赛中。

## 验收结果

13 份原版比赛录像均运行到原版比赛退出帧，累计 226,898 帧逐帧状态对照全部通过，包括回合切换及返回录像菜单。原始文件 SHA-256、每份录像帧数、测试核心哈希见 artifacts/cpp/verification/original-replays-full-original.json。

正式构建 1.0.1 的桌面和手机触控模拟测试通过。旧版 1.0.0 升级保留 score.dat 及导入录像，并复用本地游戏资源，无需重新下载完整游戏素材。共享 SDL3/WebGL2 渲染器未更换。

公开版本已更新至 1.0.1：https://api.steinsgateon.com/ （本地服务端口 3007）。实际 HTTPS 全新浏览器安装、标题、选人及实战验收通过，公网与本地 Wasm SHA-256 均为 38e00da4baae661efbed52dcb7b3bf7a200914543e26b294ef02dbed4abb06a9。实际手机驱动和触控延迟仍需要测试组真机复测。以上是已执行的验收范围，不代表穷尽所有角色组合、剧情路径、图像或声音差异。
