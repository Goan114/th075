# 暂停与画质修复：萃梦想 WEB 1.0.2

这次截图中的巨大 SPELL 标签、数字和截断图形是实际的纹理资源错误，不是正常暂停画面。此前测试把不同资源库映射为同一个编号，漏掉了这个问题；本轮已改为独立图集对照，并执行真实浏览器截图验证。

## 修改

- BattleHudStatus.cpp 普通、故事、续关、练习暂停必须读取人物肖像资源的最后一张招式表。此前误用 battle.dat 的同编号图片，画出了巨大标签和数字。普通双方、故事单方及练习均修正。原版 0x441910 和 0x448710 读取人物 +0x534 资源，战斗 HUD 资源在场景 +8；这些地址仅供测试取证。
- CinemaDrawing.cpp、ResultDrawing.cpp 的原版过滤编号从 1 开始，现代语义枚举从 0 开始。已改用具名 Linear/Nearest，恢复每批过滤设置；结果截图画完正确恢复最近邻，后续标题、人物、HUD 不再继承平滑过滤。
- Canvas 使用 pixelated 避免浏览器再次平滑缩放。默认绘制 1280×960，启动器可选 640×480。原版低分辨率素材本身的像素仍保留，高分辨率输出不凭空增加素材细节。

共用 portable/sdl/Renderer.cpp 未改动，仍为 C++ 具名游戏逻辑、CPU 顶点计算合批、SDL3 / WebGL2 与 glBufferData 上传。生产版不调用 D3D8/9、原版 EXE 或 x86 解释器。

## 本轮实际验证

- 独立 HUD、人物精灵、肖像资源库的原版对照：1600 组 HUD/暂停场景和 2000 组符卡/计时场景通过。修复前同一测试在暂停纹理编号上失败，修复后通过。
- 开场/制作人员名单、结果/排行榜/录像列表/命名/转场逐批几何与过滤状态通过。
- 背景、选人、人物肖像、HUD 数字、绘制顺序的扩展对照通过。
- 原版开场与击倒完整时间线共 320 帧、960 次重复渲染通过。开场最后旋转放大的 GO 图形在暂停时会停住，这是原版动画行为，不能作为错误图层隐藏。
- 两种分辨率各自验证五种可暂停模式、十一名角色、原版录像暂停、冻结/选择/恢复、三次败北到续关、续关后胜利/结果/返回标题。
- 从选人、设置、Music Room、战绩、录像、开场回到标题，整张 640×480 标题像素与干净标题一致。
- 五种模式从暂停退出到选人并返回标题，以及对战/故事“保存并退出”到录像命名、保存和回标题通过。Arcade 完整对手流程、胜利对话及保存通过。

浏览器测试使用桌面 Chromium 模拟手机视口和触摸，不等于手机真机驱动/帧率验收。此前 1.0.1 的 13 份原版比赛、226898 帧属于已有游戏逻辑证据，本轮没有把它们写成重新运行的结果。
