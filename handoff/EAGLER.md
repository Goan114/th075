# TH075 Eagler adapter

Development belongs on `eagler`. `main` retains the original public source
snapshot (`7c6127c7c71f89c8a790ba692d465bff75891096`) and has a separate upstream
reference worktree. The launcher integration starts at upstream
`b667ab07cb7cf11f9220d11e3a64602cc6331792`. Dependency identities are recorded in
`dependencies.json`; the shared-library checkout is never replaced with an
arbitrary sibling branch.

## Build and run

Use Python 3.10+ and Node 22+ with the matching private development package:

```powershell
python tools/import-local-inputs.py "D:/path/to/TH075-1.0.4-development-20261012" --include-toolchain
npm run build
npm run package:runtime
npm run prepare:content
npm run dev
```

`npm run dev` uses the sibling `eagler-touhou` checkout, builds its current UI,
and serves the development site at `http://127.0.0.1:18175/`. Override its location
with `EAGLER_LAUNCHER_ROOT`, and its port with `EAGLER_TH075_PORT`. Use the
`eagler` integration branch in that checkout (`13a21ce758e40eaab25d459724dd9da315c33b4c`). Its existing `main` is preserved.

To regenerate/check the common browser sources, materialize the exact
`eagler-common` revision from `dependencies.json` in a separate checkout and set
`EAGLER_COMMON_ROOT`. Run `node tools/sync-common.mjs` or
`npm run check:common`. The keyboard module is generated by the shared authority;
`save-sync.mjs` is copied unchanged with its MIT license retained.

## Original controls and presentation

The control markup, descriptions and default geometry come from the development
package's `th075_web/launcher/public/index.html` and the final fighting-control
block in `styles.css`. Buttons are 60 x 60 circles in a 216 x 170 right-hand
cluster: A at (0,70), B at (65,5), C at (130,70), D at (65,110). The left joystick
remains the default. The shared layout editor owns any deliberate user layout.

| Button | Default key | Original label |
| --- | --- | --- |
| A | Z | 轻攻击 |
| B | X | 重攻击 |
| C | C | 弹幕 |
| D | V | 冲刺 |

All four buttons are held inputs and may be combined. A confirms, B cancels,
ESC pauses, and Ctrl fast-forwards dialogue/Replay. The help text retains the
development package's direction, guard, menu, dialogue and Option descriptions;
shooting-game auto-fire, Bomb and slow-movement descriptions are not shown for
this control profile. The ordinary Runtime retains the original game logic,
native command recognition and `.rep` representation.

## Integration boundaries

- The current shared launcher owns the product card, options, Package Store,
  input transport, layout editor and save/Replay management.
- Directory Runtime + `retail-memory`; the layout is
  `sha256-31f13ab255731fc7490659c30a8105ce7377a873c26ef64c8c7af1e9e0669759`.
- `portable/prepare-content.mjs` creates a local indexed `th075.data` containing
  Japanese base/patched compressed resources, measured game glyphs and the music
  loop catalog. The 34 OGG files are separate Package components. Music is OGG
  or none; all declared tracks are acquired before an OGG launch.
- Code-only Runtime output is `build-eagler/`, with a closed `runtime-files.json`
  set. Game inputs are in `assets-ogg/`. Both are ignored by Git.
- The shell checks origin, parent Window, protocol, game and navigation epoch;
  binds managed DATA to that epoch; and rejects live reconfiguration.
- Save/config/Replay access is restricted to `/savesth075`; import uses the
  native validators. IDBFS synchronization uses the pinned common helper.
- Touch action bits are distinct from keyboard ownership. Cancelled touch does
  not release a physically held keyboard action. Gamepad face buttons use SDL's
  standard South/East/West/North mapping instead of raw device button numbers.
- `--eagler` keeps original acceptance hashes enforced for game/shared sources;
  SDL adapter sources are tracked in the new build's own hash manifest. This is
  not a claim that the original acceptance run covered later platform changes.

## Verification and scope

`npm run test:adapter` verifies DATA indices, foreign-Window buffers and resource
hash rejection. Launcher service tests cover simultaneous four-button presses,
iOS ownership, cancellation, settings, preparation and Replay management.
`npm run test:th075:browser` in the launcher uses the real rebuilt Runtime with
desktop OGG and emulated-mobile no-music lanes. Set
`EAGLER_TH075_TEST_REPLAY` to an original `.rep` for import/read/list/remove/sync
round trips. Browser assertions also cover the original button geometry and
descriptions, epoch rejection, native file validation and persistence through
new Runtime documents. These lanes require the private prepared content and
the running development server.

Runtime file identities, DATA-provider declaration and navigation-epoch shell
contracts are checked with the shared launcher validators. The full launcher
repository/workspace gates were also attempted; their remaining unrelated
upstream inventory issue is the already tracked, undeclared `public/assets/th20-card.webp`, and older
full-help DOM snapshots retain preexisting THPrac markup expectations.

Not claimed: full Replay golden `quick`/`daily` acceptance, high-refresh
presentation, physical mobile/gamepad testing, or a new public deployment.
MIDI, Multiplayer and THPrac are not advertised in this ordinary adapter build.
Static thcrap language packs are described in [THCRAP.md](THCRAP.md); the
development package's older Chinese overlay remains a separate source profile.
Formal all-title Runtime Release and Hosted/External/Import release assembly
still require the other registered titles' matching build inputs. The local
TH075 launcher/Package Store path is executable independently of those inputs.
## 2026-10-15 camera and rapid-input regression fixes

A loaded StoryEnvironment must be attached before BattleScene::initialize, so
its non-story initialization can release cinematic camera overrides. Destroying
character/session resources also clears the retained story environment. Camera
math and character/game logic remain unchanged.

`npm run test:camera` builds a separate, non-publishable `--test-harness` using
the same release game objects, then verifies fresh Practice against Story →
title → Practice. This requires the private imported assets and the sibling
Launcher's Chromium/Puppeteer dependencies. The original implementation fails
this regression because the Story lock remains enabled; the fixed camera is
unlocked at y=300, matching a fresh Practice session. `npm run build` followed
by `npm run package:runtime` still produces a code-only Runtime with no probe
exports; the test build never replaces production build provenance.

The Runtime uses the Launcher's optional, epoch-bound same-origin immediate
input bridge, with the same dispatcher and postMessage fallback. Input requests
with reply IDs retain the queued/RPC path. The Launcher drops redundant capture
release packets and batches native button HUD notifications per animation frame;
native down/up edges remain immediate. Emulated-mobile browser regression
covers actual menus and battles, all 240 edges from 120 rapid taps, zero queued
input messages, and stale bridge epoch rejection. This is not a physical-phone
frame-rate guarantee.

## 2026-10-15 standalone rapid-tap scheduling

SDL 3.4.2 Emscripten_GLES_SwapWindow calls emscripten_sleep(0) by default
when Asyncify is linked. The adapter already owns a requestAnimationFrame loop,
but awaited every swap timer before requesting the next frame. Mobile tap
scheduling can postpone that timer while joystick movement establishes a gesture.
Set SDL_HINT_EMSCRIPTEN_ASYNCIFY to 0 before graphics initialization to disable
the redundant swap yield. Asyncify remains linked for asynchronous asset reads.
The launcher test test-th075-touch-scheduling-browser.mjs drives browser-managed
touches and gates zero-delay timers during isolated taps. Before the change this
reduces simulation to about 3.5 FPS while rAF continues; fixed builds must retain
over 45 FPS for each A/B/C/D button and the joystick comparison.

## 2026-10-15 menu transition warmup

Fixed menu textures are decoded and uploaded once during Runtime initialization,
then shared by scene banks through a retained owner. The cache contains only
title, select/selectchar/selectbg, replay, music, resultlist, option and load
artwork. Music-room metadata and the ten ranking characters' card lists are
retained as small decoded resources. Fighter/stage banks still release normally.
The initial loading phase performs this work before accepting menu input.

The launcher browser regression test-th075-menu-transitions-browser.mjs visits
Story selection, Replay, Music Room, rankings and Options twice using real
keyboard commands, checks zero asset reads on entry, records tick duration and
WASM heap size, and captures first-entry screens. The original adapter rereads
all three selection packs on every entry (204 ms cold, 183 ms repeated on the
local test machine). Set TH075_MENU_BASELINE=1 only to collect unfixed evidence.
